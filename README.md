# 📈 日本株 本日の注目銘柄トップ10

毎朝7時に日本株の全銘柄（プライム・スタンダード・グロース）を自動で調べ、
**「高値更新 × 出来高増加 × 業績改善」** がそろった銘柄をトップ10としてスマホ向けサイトに表示します。
**なぜ選ばれたのか** を日本語で説明し、過去の成績（バックテスト）も表示します。

- 費用：**0円**（GitHub の無料枠のみ・APIキー不要）
- 必要なもの：GitHubアカウント（無料）だけ。プログラミングは不要です
- 売買は自動で行いません。表示を見て、ご自身で判断します

> ⚠️ 投資助言ではありません。株は元本割れの可能性があります。過去の成績は将来を保証しません。

---

## しくみ（全体像）

```
毎朝7時（GitHub Actions）
  ① JPXの上場銘柄一覧を取得 → ② Yahoo!ファイナンス(yfinance)で全銘柄の株価を取得
  ③ 高値更新・出来高・移動平均でテクニカル点を計算 → 売買代金1億円未満などを除外
  ④ 上位候補だけ業績（営業利益・時価総額）を取得して加点、赤字企業を除外
  ⑤ 100点満点で順位付け → 理由・解説・リスクの文章を自動生成
  ⑥ docs/index.html を作成 → GitHub Pages がスマホで見られるサイトとして公開
毎週日曜 3時：過去2年の再現検証（バックテスト）を更新
```

## 導入手順（所要 約20分）

### ステップ1：GitHubアカウントとリポジトリを作る
1. https://github.com でアカウントを作成（無料）。
2. 右上の **＋ → New repository**。
3. Repository name に `jp-stock-top10`（好きな名前でOK）。
4. **Public** を選ぶ（※無料プランで GitHub Pages を使うには Public が必要です。サイトの内容はネット上で誰でも見られます。パスワード・APIキーは使わないので情報漏えいの心配はありません）。
5. **Create repository**。

### ステップ2：ファイルをアップロードする
1. 配布した zip を解凍します。
2. 作成したリポジトリのページで **uploading an existing file**（または Add file → Upload files）。
3. 解凍したフォルダの**中身をすべて**ドラッグ＆ドロップ → **Commit changes**。

> ⚠️ **最重要：`.github` フォルダが見えない・アップロードされない場合**
> `.github` は隠しフォルダです。Mac は Finder で `Command + Shift + .`（ピリオド）、Windowsはエクスプローラーの「表示 → 隠しファイル」で見えるようになります。
> それでもうまくいかない場合は、GitHub上で **Add file → Create new file** を開き、ファイル名欄に
> `.github/workflows/daily.yml` と入力（`/` を打つとフォルダになります）して中身を貼り付け → Commit。`weekly_backtest.yml` も同様に作ります。
>
> 確認：リポジトリ画面に `.github` フォルダがあり、中に2つの `.yml` があればOK。

### ステップ3：自動更新が結果を保存できるようにする
1. リポジトリの **Settings → Actions → General**。
2. 一番下の **Workflow permissions** で **Read and write permissions** を選び **Save**。

### ステップ4：GitHub Pages を有効にする（サイト公開）
1. **Settings → Pages**。
2. **Source** は **Deploy from a branch**。
3. **Branch** を `main`、フォルダを **`/docs`** にして **Save**。
4. 数分後、同じ画面に `https://（ユーザー名）.github.io/jp-stock-top10/` と表示されます。これがサイトのURLです。

### ステップ5：初回の手動実行
1. リポジトリの **Actions** タブ → 左の **weekly-backtest** → **Run workflow**（緑ボタン）。
   過去2年の再現検証が走ります（10〜30分）。
2. 終わったら **daily-update** → **Run workflow**。
   ランキングが生成されます（10〜20分）。緑のチェックが付けば成功です。
3. 上のサイトURLを開きます（反映に1〜2分かかることがあります）。

> 「Actions」タブに「I understand my workflows…」と出た場合は、緑ボタンを押して有効化してください。

### ステップ6：スマホで使う
- サイトURLをブックマーク。
- iPhone：Safariの共有ボタン →「ホーム画面に追加」／Android：Chromeのメニュー →「ホーム画面に追加」。
- 以降は毎朝7時台に自動更新されます（GitHubの混雑で数十分遅れることがあります）。

## API設定方法

**このシステムは APIキーが不要です。** 次の無料の公開データだけを使います。

| データ | 取得元 | 備考 |
|---|---|---|
| 銘柄一覧・業種 | JPX公式の上場銘柄一覧（Excel） | 週1回更新 |
| 株価・出来高・指数 | yfinance（Yahoo!ファイナンス） | 非公式。遅延・欠損・仕様変更あり |
| 営業利益・時価総額 | yfinance | 銀行・保険などは営業利益が無く「未確認」表示 |
| チャート | 自前のSVG ＋ TradingView埋め込み | ボタンを押した時だけ読み込み |

将来 J-Quants など**キーが必要なAPI**に切り替えるときは、キーをコードに書かず、
**Settings → Secrets and variables → Actions → New repository secret** に登録し、
`daily.yml` の該当ステップに `env: { JQUANTS_KEY: ${{ secrets.JQUANTS_KEY }} }` を足します。

## 画面の見方

- **上部**：更新日時、データ基準日（前営業日の終値）、市場状況コメント（追い風／中立／逆風）
- **各銘柄カード**：順位・銘柄名・コード・株価・**スコア（100点満点）**・強気判定（緑=強気 / 黄=やや強気 / 灰=中立）
  - **なぜ選ばれた？**（✅の理由）／**初心者向け解説**（100文字以内）／**リスク**（赤）／撤退ラインの目安
  - ローソク足（25日線・75日線・出来高付き）。ボタンで TradingView の本格チャートも表示
- トップ3は枠の色と大きさで強調。ダークモード・スマホ幅に対応（右上の🌓で切替）
- 業種ランキング／テーマランキング／**過去の検証結果**／点数の見方

### スコアの計算（元の仕様どおり）
| 項目 | 配点 |
|---|---|
| 高値更新 | 60日高値 +30 ／ 30日高値 +15 |
| 出来高（当日 ÷ 20日平均） | 2倍以上 +20 ／ 3倍以上 +30 |
| トレンド（株価＞25日線＞75日線） | +20 |
| 営業利益の前年比 | +20%以上 +15 ／ +50%以上 +25（黒字転換 +15） |
| 時価総額 | 100億円以上 +5 ／ 500億円以上 +10 |

- 各項目は**高い方だけ**加点（重複なし）。合計の最大が115点になるため、**100点満点に換算**して表示します（`config.yml` の `normalize_to`）。
- 除外：赤字（直近1年の営業利益が0以下）／売買代金（20日平均）1億円未満／株価100円未満／銘柄名に「監理」「整理」を含む／`data/exclude_codes.txt` の銘柄。
- 強気判定：70点以上＝強気、50点以上＝やや強気。**RSIが80以上・25日線から25%以上乖離（過熱）、または市場全体が下落基調のときは一段階下げます。**

### バックテスト（2種類）
1. **過去再現**（毎週自動）：過去2年、毎週その時点のトップ10を作り直し、「翌営業日の始値で買い、1週間・1か月・3か月後の終値で売る」場合の成績を、TOPIXと並べて表示。
2. **実績の記録**（毎朝自動）：このサイトが実際に出したトップ10を `data/history/` に保存し、日数が経ってから騰落率を計算。**最も正直な成績表**ですが、貯まるまで数週間〜数か月かかります。

過去再現の注意点（画面にも表示されます）：現在の上場銘柄で計算（上場廃止は含まれず甘く出る）／業績点は含まない（テクニカル点のみ）／往復0.2%のコストは引くが、ストップ高で買えない等の実際のズレは含まない。

## 設定の変え方（config.yml）

メモ帳等で `config.yml` を開き、数字を書き換えて保存（GitHub上では鉛筆アイコンで編集 → Commit）します。

| やりたいこと | 場所 |
|---|---|
| 表示銘柄数を変える | `top_n` |
| 売買代金の下限を上げる（例：5億円） | `filters.min_turnover_yen: 500000000` |
| 配点を変える | `scoring` |
| 強気／やや強気のライン | `bull` |
| 特定の銘柄を除外 | `data/exclude_codes.txt` に1行1コード |
| テーマを追加 | `themes.yml`（コードは `"8035"` のように引用符で囲む） |
| 色を変える | `static/style.css` の最初の `:root { ... }` |

## メンテナンス

### 毎日〜毎週（1分）
- 朝サイトを開き、**更新日時が今日**になっているか確認。古いと画面上部に赤い警告が出ます。
- 失敗するとGitHubから**メールが届きます**（Actionsが赤い✕のとき）。

### よくあるトラブル
| 症状 | 原因と対処 |
|---|---|
| 更新されない・Actionsが✕ | Actions → 失敗した実行 → ログを確認。多くは Yahoo! 側の一時制限。**時間をおいて Run workflow** を押せば直ります。成功率が低いときは意図的に更新を止める設計なので、古い画面が残るだけで壊れた表示にはなりません |
| `Permission denied` / push失敗 | ステップ3（Read and write permissions）を確認 |
| サイトが404 | ステップ4（Pages: main / docs）を確認。初回実行後に数分待つ |
| 数か月たって自動実行が止まった | 60日間リポジトリに動きがないと定期実行が無効化されます（通常は毎朝のコミットで防げます）。Actions → 該当ワークフロー → **Enable workflow** |
| 銘柄一覧の取得に失敗 | JPXのExcelの形式変更の可能性。保存済みの一覧で動き続けますが、1か月続くなら `src/universe.py` の見直しが必要 |
| 特定銘柄の業績が「未確認」 | 銀行・保険・新規上場などで営業利益が取れない銘柄。仕様です |
| 監理銘柄が出た | `data/exclude_codes.txt` にコードを追加（JPXの「監理銘柄・整理銘柄一覧」で確認） |

### 月1回
- `themes.yml` を見直す（新しいテーマ・上場廃止銘柄の整理）。
- 画面の「過去の検証結果」を確認し、成績が悪化していないか見る。

### 年1回
- yfinance は非公式のため、仕様変更で止まることがあります。止まったら Actions のログのエラー文を ChatGPT/Claude などに貼って相談すると、修正箇所がわかります。

## 使うときの心得（利益を出すために）
1. 点数は「条件がそろっているか」であって、**上がる保証ではありません**。リスク欄と撤退ライン（25日線割れ）を必ず見る。
2. 「逆風」の日、RSIが80超の銘柄、前日に急騰した銘柄の**飛びつき買いは避ける**。
3. 1銘柄に資金を集中させない（目安：総資金の5〜10%以内）。
4. まず**数週間は買わずに観察**し、「実績の記録」の数字と自分の感覚を合わせる。
5. 改善案は `IMPROVEMENTS.md` を参照。
