# 📈 日本株 本日の注目銘柄トップ10

毎朝7時に日本株の全銘柄（プライム・スタンダード・グロース）を自動で調べ、
**「好材料（業績・株主還元）を持ちながら、健全な押し目を形成中」** の銘柄をトップ10としてスマホ向けサイトに表示します。
「今強い銘柄」ではなく「押し目の良い銘柄」が主役です（従来の強さスコアは補助指標として各カードに残しています）。
**なぜ選ばれたのか** を日本語で説明し、過去の成績（バックテスト）も表示します。

- 費用：**0円**（GitHub の無料枠のみ・APIキー不要）
- 必要なもの：GitHubアカウント（無料）だけ。プログラミングは不要です
- 売買は自動で行いません。表示を見て、ご自身で判断します

> ⚠️ 投資助言ではありません。株は元本割れの可能性があります。過去の成績は将来を保証しません。

## しくみ（全体像）

```
毎朝7時（GitHub Actions）
  ① JPXの上場銘柄一覧を取得 → ② Yahoo!ファイナンス(yfinance)で全銘柄の株価を取得
  ③ 高値更新・出来高・移動平均でテクニカル点を計算 → 売買代金1億円未満などを除外
  ④ 上位候補だけ業績（営業利益・時価総額）を取得して加点、赤字企業を除外
  ⑤ 100点満点で順位付け → 理由・解説・リスクの文章を自動生成
  ⑥ docs/index.html を作成 → GitHub Pages がスマホで見られるサイトとして公開
毎週日曜 3時：過去5年の再現検証（バックテスト）を更新
```

## 導入手順（所要 約20分）

### ステップ1：GitHubアカウントとリポジトリを作る
1. https://github.com でアカウントを作成（無料）。
2. 右上の **＋ → New repository**。
3. Repository name に `jp-stock-top10`（好きな名前でOK）。
4. **Public** を選ぶ（※無料プランで GitHub Pages を使うには Public が必要です。サイトの内容はネット上で誰でも見られます。パスワード・APIキーは使わないので情報漏えいの心配はありません）。
5. **Create repository**。

### ステップ2：ファイルをアップロードする
1. 配布した zip を解凍します。
2. 作成したリポジトリのページで **uploading an existing file**（または Add file → Upload files）。
3. 解凍したフォルダの**中身をすべて**ドラッグ＆ドロップ → **Commit changes**。

> ⚠️ **最重要：`.github` フォルダが見えない・アップロードされない場合**
> `.github` は隠しフォルダです。Mac は Finder で `Command + Shift + .`（ピリオド）、Windowsはエクスプローラーの「表示 → 隠しファイル」で見えるようになります。
> それでもうまくいかない場合は、GitHub上で **Add file → Create new file** を開き、ファイル名欄に
> `.github/workflows/daily.yml` と入力（`/` を打つとフォルダになります）して中身を貼り付け → Commit。`weekly_backtest.yml` も同様に作ります。
>
> 確認：リポジトリ画面に `.github` フォルダがあり、中に2つの `.yml` があればOK。

### ステップ3：自動更新が結果を保存できるようにする
1. リポジトリの **Settings → Actions → General**。
2. 一番下の **Workflow permissions** で **Read and write permissions** を選び **Save**。

### ステップ4：GitHub Pages を有効にする（サイト公開）
1. **Settings → Pages**。
2. **Source** は **Deploy from a branch**。
3. **Branch** を `main`、フォルダを **`/docs`** にして **Save**。
4. 数分後、同じ画面に `https://（ユーザー名）.github.io/jp-stock-top10/` と表示されます。これがサイトのURLです。

### ステップ5：初回の手動実行
1. リポジトリの **Actions** タブ → 左の **weekly-backtest** → **Run workflow**（緑ボタン）。
   過去5年の再現検証が走ります（20〜60分かかることがあります）。
2. 終わったら **daily-update** → **Run workflow**。
   ランキングが生成されます（10〜20分）。緑のチェックが付けば成功です。
3. 上のサイトURLを開きます（反映に1〜2分かかることがあります）。

> 「Actions」タブに「I understand my workflows…」と出た場合は、緑ボタンを押して有効化してください。

### ステップ6：スマホで使う
- サイトURLをブックマーク。
- iPhone：Safariの共有ボタン →「ホーム画面に追加」／Android：Chromeのメニュー →「ホーム画面に追加」。
- 以降は毎朝7時台に自動更新されます（GitHubの混雑で数十分遅れることがあります）。

## API設定方法

**このシステムは APIキーが不要です。** 次の無料の公開データだけを使います。

| データ | 取得元 | 備考 |
|---|---|---|
| 銘柄一覧・業種 | JPX公式の上場銘柄一覧（Excel） | 週1回更新 |
| 株価・出来高・指数 | yfinance（Yahoo!ファイナンス） | 非公式。遅延・欠損・仕様変更あり |
| 営業利益・時価総額 | yfinance | 銀行・保険などは営業利益が無く「未確認」表示 |

将来 J-Quants など**キーが必要なAPI**に切り替えるときは、キーをコードに書かず、
**Settings → Secrets and variables → Actions → New repository secret** に登録し、
`daily.yml` の該当ステップに `env: { JQUANTS_KEY: ${{ secrets.JQUANTS_KEY }} }` を足します。

## 画面の見方

- **上部**：更新日時、データ基準日（前営業日の終値）、市場状況コメント
- **各銘柄カード**：順位・銘柄名・**総合点（並び順）**・判定（押し目良好／押し目候補／様子見）
  - **【強み】**（✅ 増配・黒字転換・自社株買い・上方修正・最高益更新・大型受注 など）
  - **【押し目状況】**（✅ 高値から-8%／50日線付近／出来高縮小 など）
  - **【注意事項】**（⚠ 下方修正履歴・決算接近・ボラティリティ上昇・急騰後 など）
  - なぜ選ばれた？（100文字以内）／撤退ラインの目安／ローソク足（25日線・50日線）
  - 「補助指標」を開くと従来の「今強い」スコアが見られます
- **ランキングの変化**：各カードに前回からの順位変化（▲上昇／▼下降／＝変わらず・総合点の増減）を表示し、**新規ランクイン銘柄は金色の枠と「🆕 新規ランクイン！」の帯**で目立たせます。上部に変化の件数、②の欄に一覧（新規・急上昇・急下降・ランクアウト）が出ます。前回の記録がない初日は表示されません
- **除外銘柄**：TOB等で除外した銘柄は `docs/excluded_events.csv`（サイトからもリンク）に一覧出力されます

### スコアの計算（総合点 ＝ 押し目スコア100点 ＋ イベント点 −30〜＋20）
| 押し目スコア | 配点 | 内訳 |
|---|---|---|
| 長期トレンド | 20 | 50日線＞200日線 +14、株価＞200日線 +3、200日線が上向き +3 |
| 高値からの調整 | 25 | 52週高値から**−5%〜−15%が満点**。浅すぎ・深すぎは低評価 |
| 50日線に接近 | 15 | 50日線から−3%〜+4%で満点 |
| 出来高の収縮 | 10 | 調整中に直近10日の出来高が50日平均の0.7倍以下で満点 |
| 業績・還元 | 20 | 黒字・黒字転換・最高益・増配・連続増配・自社株買い・上方修正（上限20） |
| 地合い | **−15〜+10** | 加点：TOPIX（追い風+6／中立+3）＋日経平均が50日線の上 +4。**減点：TOPIXが75日線の下 −10、200日線の下 −5、日経平均が50日線の下 −3**（逆風時は全銘柄の総合点が下がります） |

**減点**：5日で+12%以上の急騰 −10／20日で+25%以上 −15／高値から25%以上下落 −15／出来高急増だけの上昇 −10／調整中の出来高膨張 −6／**決算まで3営業日以内 −10、5営業日以内 −5**（窓開けリスク）。

| TDnetイベント点（上位50銘柄のみ解析） | 点 |
|---|---|
| 上方修正 | +6 |
| 増配／自社株買い | +5 |
| 大型受注／業務提携／設備投資・工場増設 | +4／+3／+3 |
| 新製品／株式分割 | +2／+2 |
| **下方修正**（さらに−10の追加減点） | **−10** |
| **減配** | **−10** |
| 方向が判別できない修正（「修正あり（未判定）」と表示） | −3 |

**㉑ 精度向上**：①イベントは鮮度で重み付け（30日以内100%／90日以内70%／180日以内40%／それ以前0%）。②自社株買いは時価総額比（1%未満+1／1〜3%+3／3%以上+5、不明は+1）。③**直近30日以内の下方修正（TDnet開示、またはアナリスト予想EPSが30日前比−3%以下）は総合点からさらに−15点し、判定を「様子見」に**。④修正の増額・減額は、タイトルの語 → 開示PDFの「前回→今回」の表・△記号 → アナリスト予想の変化 の順に判定。⑤撤退ラインは「50日線（なければ200日線）−ATR(14日)」で表示（現在値・ATR・推奨撤退ライン・リスク幅%）。

合計は +20／−30 で頭打ち。下方修正・減配がある銘柄は判定を「様子見」に下げます。
**除外（ランキング対象外）**：TOB・公開買付・MBO・完全子会社化・株式交換・スクイーズアウト・上場廃止関連・監理銘柄・整理銘柄。
値はすべて `config.yml`（`pullback:` と `tdnet:`）で変更できます。

### TDnet（適時開示）について（重要）
- 流れ：全銘柄スクリーニング → 押し目スコア → 上位候補 → **TDnet解析** → 除外判定 → イベント評価 → 最終ランキング。TDnetは**補助レイヤー**で、銘柄を探す用途には使いません。
- 取得元は既定で Yanoshin WebAPI（`config.yml` の `tdnet.base_url`）。JPX公式の無料閲覧は直近31日分のみのためです。**このAPIの応答形式は開発環境から確認できていません**。初回は `python -m src.tdnet 7203` で動作確認してください。
- 取得できない場合は画面上部に「TDnet未確認」の警告を出し、価格固着（TOBの疑い）の検出やJPX監理銘柄一覧などの代替チェックだけで動きます。

### 業績イベントのデータについて（重要）
- 無料のYahoo!ファイナンス(yfinance)には、日本企業の「営業利益の会社予想」「上方修正の履歴」「最高益」の正式なデータがありません。
  そのため **アナリストのEPS予想・決算履歴・配当履歴で代替** しています。画面で「予想」バッジの付く項目が該当します。
- 小型株など予想が取れない銘柄は、直近12か月の実績で判定します（黒字転換は +8）。取得できない項目は評価を単にスキップします。
- 配当（増配率・連続増配）もYahooの履歴が元で、決算期のずれや分割の影響を受けることがあります。精度を上げたい場合は J-Quants などの有料データへの切替を検討してください。

### バックテスト（2種類）
1. **過去再現**（毎週自動・1/3/5/10年）：毎週その時点の**押し目トップ10**（従来のトップ10は参考表示）を作り直し、「翌営業日の始値で買い、約1か月（20営業日）保有→入れ替え」を繰り返した場合の **勝率・平均利益率・平均損失率・PF・最大ドローダウン・シャープレシオ・年率リターン** を期間別に表示。TOPIXとの比較も表示します。
2. **実績の記録**（毎朝自動）：このサイトが実際に出したトップ10を `data/history/` に保存し、日数が経ってから騰落率を計算。**最も正直な成績表**ですが、貯まるまで数週間〜数か月かかります。

過去再現の注意点（画面にも表示されます）：現在の上場銘柄で計算（上場廃止は含まれず甘く出る）／**押し目スコアの技術部分（80点分）だけ**（業績・TDnetは含まない）で計算（業績・イベントの過去データは無料で入手できない）／往復0.2%のコストは引くが、ストップ高で買えない等の実際のズレは含まない。
10年分の取得は時間がかかります（30〜90分）。重い場合は `config.yml` の `backtest.replay_years` を 5 にしてください（10年の列は「—」表示になります）。

## 設定の変え方（config.yml）

メモ帳等で `config.yml` を開き、数字を書き換えて保存（GitHub上では鉛筆アイコンで編集 → Commit）します。

| やりたいこと | 場所 |
|---|---|
| 表示銘柄数を変える | `top_n` |
| 除外条件（売買代金・出来高・低位株など） | `filters`、赤字の扱いは `fundamentals` |
| 高値更新の期間（20/60/252日） | `scoring.trend.windows` |
| 配点を変える | `weights`（合計100）と `scoring`。合計がずれると起動時にエラーで教えてくれます |
| イベントの点数・同時発生ボーナス | `events` |
| 期待値点の式（勝率・流動性係数） | `expected_score` |
| 強気／やや強気のライン | `bull` |
| 特定の銘柄を除外 | `data/exclude_codes.txt` に1行1コード |
| テーマを追加 | `themes.yml`（コードは `"8035"` のように引用符で囲む） |
| 色を変える | `static/style.css` の最初の `:root { ... }` |

## メンテナンス

### 毎日〜毎週（1分）
- 朝サイトを開き、**更新日時が今日**になっているか確認。古いと画面上部に赤い警告が出ます。
- 失敗するとGitHubから**メールが届きます**（Actionsが赤い✕のとき）。

### よくあるトラブル
| 症状 | 原因と対処 |
|---|---|
| 更新されない・Actionsが✕ | Actions → 失敗した実行 → ログを確認。多くは Yahoo! 側の一時制限。**時間をおいて Run workflow** を押せば直ります。成功率が低いときは意図的に更新を止める設計なので、古い画面が残るだけで壊れた表示にはなりません |
| `Permission denied` / push失敗 | ステップ3（Read and write permissions）を確認 |
| サイトが404 | ステップ4（Pages: main / docs）を確認。初回実行後に数分待つ |
| 数か月たって自動実行が止まった | 60日間リポジトリに動きがないと定期実行が無効化されます（通常は毎朝のコミットで防げます）。Actions → 該当ワークフロー → **Enable workflow** |
| 銘柄一覧の取得に失敗 | JPXのExcelの形式変更の可能性。保存済みの一覧で動き続けますが、1か月続くなら `src/universe.py` の見直しが必要 |
| 特定銘柄の業績が「未確認」 | 銀行・保険・新規上場などで営業利益が取れない銘柄。仕様です |
| 監理銘柄が出た | `data/exclude_codes.txt` にコードを追加（JPXの「監理銘柄・整理銘柄一覧」で確認） |

## 使うときの心得（利益を出すために）
1. 点数は「条件がそろっているか」であって、**上がる保証ではありません**。リスク欄と撤退ライン（25日線割れ）を必ず見る。
2. 「逆風」の日、RSIが80超の銘柄、前日に急騰した銘柄の**飛びつき買いは避ける**。
3. 1銘柄に資金を集中させない（目安：総資金の5〜10%以内）。
4. まず**数週間は買わずに観察**し、「実績の記録」の数字と自分の感覚を合わせる。
5. 改善案は `IMPROVEMENTS.md` を参照。


## 保有銘柄管理のセットアップ（㉒・スマホだけで運用できます）

サイトに「① 押し目候補トップ10」「② 急上昇・急下降」「③ 保有銘柄管理・監視」の3ブロックが並びます。
保有銘柄は**Webページの「追加」「削除」ボタン**だけで管理でき、JSONやGitHubの編集・コミットは不要です。
保存先は **Googleスプレッドシート（Apps Script）** です。端末・ブラウザ・キャッシュに依存しないので、機種変更や故障でも消えません（LocalStorageは使いません）。

### 初回だけの設定（10分・PCで行うのが楽です）
1. Googleドライブで**新しいスプレッドシート**を作る（名前は自由。例「保有銘柄」）。
2. メニュー「拡張機能」→「Apps Script」を開き、最初から入っているコードを全部消して、このリポジトリの `apps_script/Code.gs` の中身を貼り付けて保存。
3. 左の歯車「プロジェクトの設定」→「スクリプト プロパティ」→「プロパティを追加」で
   `PASSPHRASE` ＝ **12文字以上の合言葉**（他で使っていない長いもの）を登録。
4. 右上「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」→
   実行ユーザー：**自分**、アクセスできるユーザー：**全員** → デプロイ → Googleの承認を進める → 表示される **ウェブアプリのURL** をコピー。
5. GitHubで `config.yml` を開き、`holdings:` の `endpoint:` にそのURLを貼る（ここだけGitHub上の編集が1回必要です）。
6. GitHub「Settings」→「Secrets and variables」→「Actions」→「New repository secret」で
   名前 `HOLDINGS_KEY`、値 **手順3と同じ合言葉**。
7. Actionsで `daily-update` を手動実行。完了後にサイトを開き、③のブロックで合言葉を入力すれば、追加・削除と監視ができます。
   （スマホのパスワード管理に合言葉を保存しておくと、入力が楽です）

### 使い方
- 銘柄コード（例 7203）を入れて「追加」、不要になったら「削除」。
- 監視カードは**毎朝の更新時**に作られます。追加した直後は「次回更新で監視開始」と表示されます。
- 🔴売却検討 → 🟡要監視 → 🟢保有継続 の順に並びます。ランキング順位に関係なく常に表示されます。

### 追加した直後に監視カードも更新したい場合（任意）
Apps Scriptのスクリプトプロパティに `GITHUB_REPO`（例 `ikea56/top10`）と `GITHUB_TOKEN`
（GitHubの「Fine-grained personal access token」。**対象リポジトリ1つ・Actions: Read and write だけ**）を追加すると、追加・削除のたびに自動で再生成が走ります。
トークンはGoogle側（サーバー）にだけ保存され、Webページには一切入りません。
